1. Descricao do Problema

Aplicacao cognitiva que recebe consultas em linguagem natural sobre interacoes entre medicamentos e retorna classificacoes estruturadas (grave, leve/moderada, sem interacao), fundamentadas em bulas reais de medicamentos brasileiros.

Contexto profissional: Profissionais de saude e pacientes precisam verificar interacoes medicamentosas rapidamente. Bularios sao extensos e buscar manualmente e ineficiente. O sistema extrai e classifica interacoes automaticamente usando um pipeline RAG.

Os dados foram processados pelo pipeline do projeto python-processador-bulas. Trechos relevantes foram extraidos e normalizados para alimentar o sistema de recuperacao.

3. Justificativa para Uso de LLMs

O dominio farmaceutico requer precisao e rastreabilidade. LLM sao ideais porque:

  • Interpretam linguagem natural da consulta (sem necessidade de sintaxe formal)
  • Classificam interacoes com base em contexto recuperado (fundamentacao)
  • Geram saidas estruturadas (JSON) para consumo programatico
  • Reduzem alucinacao quando combinados com RAG (recuperacao de bulas reais)

5. Tarefas NLP Implementadas

  • NER (Named Entity Recognition): Extracao de nomes de farmacos usando pucpr/clinicalnerpt-chemical com agregacao de sub-tokens WordPiece
  • Classificacao de texto: 3 classes (SEM_INTERACAO, LEVE_MODERADA, GRAVE_CONTRAINDICADA)
  • Recuperacao de informacao: Busca semantica via embeddings + FAISS
  • Geracao de texto: Few-shot prompting para classificacao JSON

6.3 Estrategia de Avaliacao dos Prompts

Cada prompt foi testado com 3 consultas de dominio e avaliado por:

  • Estabilidade de saida JSON (parsing bem-sucedido)
  • Corretude semantica da classificacao
  • Presenca de hallucination vs resposta fundamentada

7.2 Parsing e Validacao

O parsing tenta tres estrategias em cascata:

  1. json.loads() direto
  2. json.loads() apos remover blocos ```json ... ```
  3. Regex "classe": (\d) como ultimo recurso

8. Modelo de Embeddings

Modelo: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2

  • 384 dimensoes
  • 12 camadas Transformer
  • Suporte a 50+ idiomas (PT-BR otimizado)
  • Normalizacao L2 -> Produto interno = similaridade cosseno

11. Pipeline RAG

11.1 Fluxo Completo

Consulta (linguagem natural)
  |
  v
[NER] pucpr/clinicalnerpt-chemical
  -> Extrai nomes de farmacos da consulta
  |
  v
[Embeddings] paraphrase-multilingual-MiniLM-L12-v2
  -> Codifica trechos de bulas em vetores densos
  |
  v
[Indice FAISS] IndexFlatIP
  -> Recupera top-K trechos mais similares
  |
  v
[Classificador] GPT4All / Heuristica
  -> Few-shot classification (Classe 0, 1 ou 2)
  |
  v
[JSON estruturado]
  -> {"classe": N, "justificativa": "...", "evidencia": "..."}

11.2 Estrategia de Chunking

  • Sentencas curtas (max 250 palavras)
  • Overlap de 1 sentenca entre chunks
  • Garante que tokenizador BERT (512 tokens) nao corta informacao no meio

11.3 Vector Store

FAISS IndexFlatIP com 384 dimensoes. Produto interno sobre vetores normalizados L2 equivale a similaridade cosseno. Indice em memoria (CPU) para demonstracao; em producao usar paginacao em disco.

15. Limitacoes da Solucao

  • NER com vocabulario limitado (nomes comerciais fora do dominio)
  • Heuristica com acuracia moderada (usada apenas como fallback)
  • Top-K fixo pode perder contextos relevantes
  • Sem avaliacao com conjunto de teste anotado

16. Melhorias Futuras

  • Fine-tuning: Treinar classificador especifico com as 5.960 bulas
  • Reranking: Segundo modelo para reordenar resultados FAISS
  • Cache Redis: TTL=7d para consultas frequentes (Dipirona, etc.)
  • Curadoria humana: Label Studio para anotar casos ambíguos
